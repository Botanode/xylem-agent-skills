# Evidence And Claims

## When to use

Make every performance, correctness and completion claim auditable.

## Procedure

1. Use existing campaign vocabulary where authoritative; distinguish inspection, implemented, built, tested, diagnostic, independently verified and certified.
2. Record commands, revisions, flags, inputs, outputs, sample paths and limitations; mark unexecuted checks as not run.
3. Never extrapolate one workload to suite parity or label unit tests end-to-end verification; keep negative evidence visible.

## Exit evidence

A claim-to-evidence mapping with explicit scope and no unsupported certification.

## Guardrails

Apply the repository rules and current mission authorization. Do not invent source facts, bypass security controls, or claim checks that were not run. If verification is unavailable, mark the result pending or blocked with the exact reason and continue independent in-scope work.
